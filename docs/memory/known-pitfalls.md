# 已知坑与判定边界
> 风险判定、审批档位与放行策略上踩过的坑与容易误判的边界。

- 2026-10-04 — `relaxed` 档其实放行删除：`find . -name '*.log' -delete`、`git rm a.txt` 都判 safe。原因：`extensions/feishu/risk.ts` 的 `RELAXED_DANGEROUS` 与 `DANGEROUS_HEADS` 只列命令名（rm/rmdir/shred/truncate/unlink），看不到 `find` 的 `-delete`/`-exec rm`、`git rm`、`rsync --delete`。结论：要「拦住删除」必须单独判这几类，不能只靠 relaxed 的内置黑名单（新增的 `auto-except-delete` 档就补了这段 `isDeleteSegment`）。
- 2026-10-04 — `allowPatterns` 只对 bash 生效，放不开 `EXFIL_TOOLS`（`feishu_send_image`）与 `HERDR_CONTROL_TOOLS`（herdr 四个控制工具），write/edit 的仓库边界也不受任何配置档位影响。结论：凡是想改变这几组工具的放行策略，纯配置表达不了，只能改 `assessRisk` 的分支（`auto-except-delete` 档就是这么加的：它刻意排在 EXFIL/HERDR 判定之前）。
- 2026-10-04 — 给 `risk.ts` 加档位时要同时改三处，漏一处就会出现「配置写了但不认」：`extensions/feishu/config.ts` 的 `ApprovalMode` 联合类型、`loadConfig` 里的取值校验与报错文案、`assessRisk` 的分支；测试在 `test/config.test.ts` 与 `test/risk.test.ts`。
- 2026-10-12 — pi 启动报 `Failed to load extension ".../pi-feishu/extensions/feishu/index.ts": Cannot find module '@larksuiteoapi/node-sdk'`：原因是 `~/.pi/agent/settings.json` 的 `packages` 直接指向本仓库源码路径（`../../workspace/github/pi-feishu`），而仓库里 `node_modules/` 不存在（未跑过 / 被清掉 `npm install`）。结论：源码方式加载的扩展，依赖必须装在本仓库里（`cd pi-feishu && npm install`），pi 不会替你装；`node_modules` 被 .gitignore 忽略，换机器或清缓存后都要重装。
- 2026-10-12 — 安装方式由 `settings.json` 的 `packages: ["../../workspace/github/pi-feishu"]` 改为 `~/.pi/agent/extensions/pi-feishu` → 仓库根 的符号链接（与 pi-ipy 统一）。前提：`package.json` 的 `pi.extensions` 必须写**文件**路径（现为 `["./extensions/feishu/index.ts", "./extensions/herdr/index.ts"]`）。目录形式 `["./extensions"]` 在符号链接方式下报 `Cannot find module '~/.pi/agent/extensions/pi-feishu/extensions'`；而把符号链接直接指向 `extensions/feishu/index.ts` 文件也不行——加载器不解析符号链接，该文件里的 `import "./config.ts"` 会以 `~/.pi/agent/extensions/` 为基准解析而报 `Cannot find module './config.ts'`。结论：只有「目录符号链接 + pi 字段为文件路径」这一种组合同构于 pi-ipy。
